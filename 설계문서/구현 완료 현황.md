### 키워드 추천 기능 상세

- **코퍼스**: `논술문서 텍스트/분야별 논증적 글쓰기 문항(...).pdf` (인문 7·사회 18·과학기술 7·융합 6 = 38문항)를 파싱해 `agent/src/agent/data/writing_prompts.json`으로 저장(리포에 커밋됨, PDF를 런타임에 다시 읽지 않음).
- **하이브리드 검색**: (1) 키워드 계층 — 38개 전체를 대상으로 한 정확/부분 문자열 스캔, (2) 시맨틱 계층 — 기존에 이미 구축돼 있던 `chromadb` 기반 RAG(`agent/src/agent/integrations/retrieval.py`, Rubric Agent가 쓰던 것과 동일한 컬렉션을 `source` 메타데이터로 구분해 재사용)로 임베딩 최근접 검색. 두 결과를 합쳐 최대 5개 반환. 실제 curl로 검증: "동물원"→정확히 1개, "동물"→키워드 3개+시맨틱 1개("길고양이 중성화", 문자열엔 "동물"이 없지만 의미상 근접) 총 4개 확인.
- **생성 폴백**: 두 계층 모두 결과가 없으면(예: "타코야끼 노점상 규제") LLM(기존 Rubric Agent와 동일한 방식으로 Claude Fable 5 호출)이 같은 형식의 새 논술 문항을 생성. 실제 호출로 검증 완료.
- **엔드포인트**: `POST /problems/recommend` (`{keyword}` → `{matches: [...], generated: {...} | null}`).
- **프론트**: `CustomProblemForm.jsx`에 "키워드별 추천 문제" 검색창 추가. 결과(추천 또는 생성) 카드를 클릭하면 제목/본문이 폼에 채워지고, 사용자가 "AI로 채점기준 생성" → "문제 저장"을 눌러 최종 확정하는 기존 흐름을 그대로 탄다. **선택 즉시 바로 답안 작성 페이지로 넘어가지는 않는다** — 추천/생성된 문제는 아직 채점 기준이 없어서, 기존 "직접 입력" 흐름(루브릭 검토 후 저장)을 그대로 재사용하는 게 더 안전하다고 판단했다.

### 참고: `db_loader.py`와의 관계

기존 `essay_problems/*.md`(대학 기출문제) 로딩 방식과 달리, 이번 코퍼스는 대학별 기출이 아니라 범용 주제 문항이라 `Problems` DB 테이블에 넣지 않고 별도 RAG 컬렉션으로만 색인했다. 사용자가 추천 문제를 실제로 "문제 저장" 하기 전까지는 DB에 아무 흔적도 남지 않는다.

## 구조적으로 함께 고친 것 (요청 기능의 전제조건)

이번 2차 요청(#3~#6)은 "세션 하나 = 문제 하나 = 여러 회차"라는 전제가 성립해야만 의미가 있는데, 구현 도중 두 가지가 이를 막고 있었다.

1. **`GET /sessions` 목록 API가 `user_answers`를 아예 내려주지 않던 버그**: 응답 스키마가 `problem`만 포함하고 있어서, "답안 기록"/"채점 비교" 목록이 항상 빈 결과로 보였을 것이다(회차 수·점수를 알 방법이 없었음). `response_model`을 상세 조회와 동일한 스키마로 바꿔 해결했다.
2. **같은 문제를 다시 선택하면 세션이 새로 생기던 문제**: `POST /sessions`가 무조건 새 세션을 만들어서, 문제 하나에 세션이 여러 개 생길 수 있었다(회차 기록이 세션별로 쪼개짐). 유저-문제 조합당 기존 세션이 있으면 그걸 재사용하도록 고쳤다. (`인터페이스 정의서.md` §4.5)

## 실행 환경 관련 참고

- 이 환경(Elice 터널)은 `/proxy/{port}/` 프리픽스를 벗겨서 백엔드로 전달하는 방식이라, `vite dev` 서버는 그대로 못 쓴다. `vite build`(base를 `/proxy/5173/`로 고정) 후 `serve -s dist`(prefix 개념 없는 단순 정적 서버)로 서빙 중이다. **즉 지금은 핫리로드가 없고, 코드가 바뀔 때마다 재빌드+재기동이 필요하다.**
- `agent/.env`에 실제 발급받은 키(Claude Fable 5 엔드포인트, Bareun 키)를 반영해 실제 AI 채점까지 동작 확인했다.
- demo 계정(`demo_user`)에 2회차까지 채점된 샘플 데이터를 만들어 뒀다 — 로그인 후 바로 답안 기록/채점 비교 화면을 확인할 수 있다.

## 아직 확인 안 된 것

- 위 신규 페이지들(`/history/:id`, `/history/:id/answers/:id`, `/compare/:id`)은 `npm run build` 통과와 코드 리뷰로만 검증했고, 실제 브라우저로 클릭해보며 확인하지는 못했다(이 환경에 브라우저가 없음). URL 접속해서 직접 눌러보고 이상 있으면 알려달라.
