# Paragraphy 인터페이스 정의서

## 1. 문서 개요

- **목적**: Paragraphy 시스템의 Frontend, API Server, 외부 AI Agent 간의 통신 인터페이스(REST API, Agent Tool 인터페이스)를 명세하고 사전 합의된 계약으로 사용
- **근거 문서**: `유스케이스 명세서.md`, `시퀀스 다이어그램.md`, `ERD.md`, `컴포넌트 설계서.md`
- **적용 원칙**:
  - 본 문서는 프론트엔드·백엔드·AI 에이전트 개발 착수 전 사전 합의 계약(Contract)으로 동작한다.
  - FastAPI의 `/docs` 자동 생성 문서는 구현 확인용으로 한정하며, 인터페이스 스펙 변경 시 본 문서를 우선 갱신한다.

---

## 2. 공통 규약

### 2.1 HTTP 요청/응답 공통

- **Base URL**: `/api/v1` (잠정)
- **Content-Type**: `application/json; charset=utf-8`
- **인증/식별자 헤더**:
  - 사용자 식별자는 요청 헤더로 전달한다.
  - Header Key: `X-User-Identifier` (또는 `identifier`)
  - 로그인(`/auth/login`) 및 공개 문제 목록 조회(`/problems`)를 제외한 모든 엔드포인트에서 필수이다.
  - 해당 식별자는 인증 토큰(JWT 등)이 아닌 대상 사용자 특정 및 세션 소유권 확인 용도이다.

### 2.2 채점 배점 표준

- 모든 채점 기준 및 루브릭 산정은 **5점 만점제(5-point scale)**를 기본 단위로 적용한다.

### 2.3 공통 에러 응답 형식

```json
{
  "error": {
    "code": "INVALID_INPUT",
    "message": "상세 오류 메시지"
  }
}
```

## 4. REST API 상세 명세

### 4.1 유저 등록 / 로그인

- **Method / Path**: `POST /auth/login`
- **설명**: 식별자를 전달하여 존재 여부를 확인하고, 없으면 신규 유저로 등록 후 로그인 처리한다.

**Request Body**
```json
{
  "identifier": "user_identifier_string"
}
```

**Response (200 OK)**
```json
{
  "user_id": "uuid-string",
  "identifier": "user_identifier_string",
  "is_new": false
}
```

---

### 4.2 문제 목록 조회

- **Method / Path**: `GET /problems`
- **Query Parameters**:
  - `university` (string, optional): 대학교명
  - `year` (integer, optional): 기출 연도
  - `type` (string, optional): 문제 유형
- **설명**: 시스템에 등록된 기출 문제 목록을 조회한다.

**Response (200 OK)**
```json
{
  "problems": [
    {
      "problem_id": "uuid-string",
      "title": "2024학년도 수시 논술 1번",
      "university": "연세대학교",
      "year": 2024,
      "content": "문제 본문...",
      "created_by_user": false
    }
  ]
}
```

### 4.3 채점 기준(루브릭) 자동 생성

- **Method / Path**: `POST /problems/rubric-gen`

**Request Body**
```json
{
  "content": "유저가 입력한 문제 본문",
  "model_answer": "선택적 모범 답안 내용"
}
```

**Response (200 OK)**
```json
{
  "rubrics": [
    {
      "criterion": "주제 부합성",
      "max_score": 5,
      "description": "제시문의 핵심 논지를 정확히 파악하여 서술하였는가"
    },
    {
      "criterion": "논리적 구성",
      "max_score": 5,

  ]
}
```

### 4.6 새 답안으로 저장 (Insert)

- **Method / Path**: `POST /sessions/{session_id}/answers`
- **설명**: 기존 답안과 분리하여 `USER_ANSWERS`에 새 답안 행을 생성하고 신규 `answer_id`를 발급한다. Frontend는 발급된 `answer_id`를 활성 답안 식별자로 설정한다.

**Request Body**
```json
{
  "user_answer": "작성한 답안 본문 텍스트"
}
```

**Response (201 Created)**
```json
{
  "answer_id": "uuid-string",
  "session_id": "uuid-string",
  "status": "draft",
  "created_at": "2026-08-15T09:05:00Z"
}
```

---

### 4.7 기존 답안 갱신 및 자동 저장 (Update)

- **Method / Path**: `PUT /sessions/{session_id}/answers/{answer_id}`
- **설명**: 현재 활성화된 `answer_id`의 답안 내용을 갱신한다. 프론트엔드의 디바운스 타이머에 의해 주기적으로 호출되어 자동 저장 역할을 수행한다.

**Request Body**
```json
{
  "user_answer": "수정된 답안 본문 텍스트"
}
```

**Response (200 OK)**
```json
{
  "answer_id": "uuid-string",
  "updated_at": "2026-08-15T09:10:00Z"
}
```

## 5. AI 에이전트 인터페이스 명세

### 5.1 Grading Agent 인터페이스

- **입력**: 문제 채점 기준, 모범 답안, 유저 답안
- **출력**: 구조화 JSON 포맷 (AgentGateway에서 응답 파싱 및 스키마 검증 수행)

**Output Schema**
```json
{
  "grammar_errors": [
    {
      "offset": 0,
      "length": 0,
      "original": "오류 원문",
      "suggestion": "수정 제안",
      "type": "맞춤법/문법 유형"
    }
  ],
  "criteria_scores": [
    {
      "criterion": "평가 항목 명칭",
      "score": 0,
      "max_score": 5,
      "rationale": "내부 보관용 상세 채점 근거",
      "improvement": "사용자 노출용 개선 방향"
    }
  ],
  "total_score": 0,
  "overall_comment": "전체 총평 문장"
}
```

### 5.2 Rubric Agent 인터페이스

- **입력**: 문제 내용(`content`), 모범 답안(`model_answer`, 선택)
- **출력**: 구조화 JSON 포맷

**Output Schema**
```json
{
  "rubrics": [
    {
      "criterion": "평가 항목 명칭",
      "max_score": 5,
      "description": "채점 세부 가이드라인 및 감점 요인"
    }
  ]
}
```

---

### 5.3 Chatting Agent Tool Calling 인터페이스

- **실행 주체**: API Server 내부 `ToolExecutor` (LLM은 직접 DB에 접근하지 않고 함수명과 인자만 지정)
- **보안 규칙**: `result_id`는 LLM 생성값을 신뢰하지 않고 ToolExecutor가 현재 요청 컨텍스트의 `result_id`로 강제 바인딩

| Tool 명칭 | 파라미터 | 반환 내용 | 조회 대상 저장소 |
|---|---|---|---|
| `get_feedback` | `result_id` (string), `fields` (array of string) | 유저 답안, 점수, 개선 방향, 근거(`rationale`) 중 요청된 필드 | Logging DB (`USER_ANSWERS`, `ANALYSIS_RESULTS`) |
| `get_problem_index` | `result_id` (string) | 문제 식별자 (`problem_id`) | Logging DB (`ANALYSIS_SESSIONS`) |
| `get_model_answer` | `problem_id` (string) | 문제 모범 답안 및 출제 내용 | 문제 DB (`PROBLEMS`) |

## 6. 호출 순서 및 상태 전이 규칙

1. **세션 및 문제 준비**:
   - 기출 문제 선택 시: `GET /problems` → `POST /sessions` (problem_id)
   - 유저 문제 생성 시: `POST /problems/rubric-gen` → 유저 루브릭 편집 → `POST /problems/custom` → `POST /sessions` (problem_id)
2. **답안 작성 및 보존**:
   - 새 답안 분리 저장: `POST /sessions/{session_id}/answers` → 신규 `answer_id` 획득
   - 작성 중 자동 저장: `PUT /sessions/{session_id}/answers/{answer_id}` (디바운스 적용)
3. **채점 요청**:
   - `POST /sessions/{session_id}/answers/{answer_id}/grading` 호출
   - 해당 답안 상태가 `submitted`로 전환되고 채점 결과가 `ANALYSIS_RESULTS`에 저장됨
4. **채팅 질의응답**:
   - `POST /results/{result_id}/chat` 호출 (채점 완료 후 발급된 `result_id` 필수)
